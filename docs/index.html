02 — the part we did not expectThe second model is a strict superset, not a contradiction

We ran the same frozen 42 candidates through both models, same prompt, same code path. Nemotron accepted every post DeepSeek accepted, and 8 more. Nothing was reversed. So this is not two models disagreeing about which posts are actionable — it is one model reaching further.

1

of the 8 extra is 1woxhua — the one real buyer the stricter model missed. That single post is the entire reason recall goes 90% → 100%.

6

are labelled not_actionable — confirmed false positives. They are the entire reason precision goes 100% → 62.5%.

1

is borderline: a human could not rule it either way, so it is excluded from every ratio rather than counted as a miss.

We are not going to publish only the flattering row. The model this competition asks us to use is the worse one on precision, and it sits directly beneath the number that looks good. Which you would prefer is not a model question — it is whether a wasted reply or a missed customer costs you more.

04 — the fine printWhat this page does not claim

  • n = 10. There are ten real buyers in this test set. That is why every figure carries a 95% interval: "100% precision" on nine posts really means "somewhere between 70% and 100%".
  • One product, five subreddits. 211 posts about exam preparation and memorisation, judged from the point of view of one flashcard tool. Nothing here generalises on its own.
  • The second test set publishes density, not a rate. It has 2 positives, so a rate there moves 50 points per relabelled row. It also turned out to be drawn from founder communities — people building these tools, not buying them.
  • Nemotron did not run on Nebius. It was served by OpenRouter, whose gateway reports provider: "Nvidia". Account creation on Nebius is unavailable to us in this region. A judge checking "runs on Nebius Token Factory" should count this submission as not meeting that clause.
  • 9 of the 91 judgements returned HTTP 503 on the first attempt ("upstream temporarily overloaded") and were retried. Both recordings now hold every verdict with zero unresolved — but the first pass was not clean.
  • One accounting gap we cannot explain. The Nemotron endpoint reports ~2,086 prompt tokens per judgement; DeepSeek reports ~406 for the same prompt. We are publishing both rather than quoting the cheaper one.

05 — check itTwo commands, no key, no network

git clone https://github.com/szkakalau/intent-radar
cd intent-radar
uv sync --extra dev

# the offline reproduction — no API key, no endpoint, no network
uv run intentradar eval score --testset einprag-2026-09-27 \
      --layers rule_v4,rule_v4+llm --min-score 3 \
      --replay data/replay/einprag-2026-09-27/rule_v4_llm

# the same thing with the NVIDIA model
uv run intentradar eval score --testset einprag-2026-09-27 \
      --layers rule_v4,rule_v4+llm --min-score 3 \
      --replay data/replay/nemotron-openrouter-2026-09-27/rule_v4_llm

A replay never fills a gap from anywhere. Change the prompt or the judge version and it fails, naming what changed, rather than quietly answering a different question.
